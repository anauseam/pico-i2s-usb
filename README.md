## Overview

This repository contains bare-metal C/C++ firmware that turns a Raspberry Pi Pico 2 and a standard I2S Analog-to-Digital Converter (ADC) into a driverless, plug-and-play USB audio interface.

It reads standard I2S digital audio data from an external ADC (such as the PCM1808 or TAA5242) and bridges it to a host computer over USB using the universal USB Audio Class 1 (UAC1) standard. The host device (Windows, macOS, Linux, or mobile) will recognize the Pico as a standard USB microphone or line-in device.

## Part 1: Quick Start (For Users)

If you simply want to build a USB audio interface and do not need to modify the code, follow these steps.

### 1. Install the Firmware

1. Download the latest `pico-i2s-usb.uf2` file from the [Releases](../../releases) page.
2. Hold down the **BOOTSEL** button on your Raspberry Pi Pico 2 and plug it into your computer via USB.
3. The Pico will appear as a removable USB drive.
4. Drag and drop the `.uf2` file onto the drive. The Pico will automatically reboot and install the firmware.

### 2. Hardware Wiring (PCM1808 Example)

The firmware is pre-configured to work with standard 24-bit I2S ADCs. Below is the default wiring guide for the common PCM1808 breakout board.

#### Data and Clock Connections

| Pico 2 Pin | PCM1808 Pin | Function |
| :--- | :--- | :--- |
| `GPIO 2` | `DOUT` | Digital Audio Data Input |
| `GPIO 10` | `BCK` | Bit Clock |
| `GPIO 11` | `LRCK` | Left/Right Word Clock (48 kHz) |
| `GPIO 12` | `SCK` / `MCLK` | System Master Clock (12.288 MHz) |

#### Power and Ground

| Pico 2 Pin | PCM1808 Pin | Function |
| :--- | :--- | :--- |
| `GND` | `GND` | Common Ground |
| `3V3(OUT)` | `3.3V` / `VDD` | Digital Logic Power |
| `VBUS` | `5V` / `VCC` | Analog Audio Power (From USB) |

#### Hardware Configuration

To ensure the PCM1808 accepts the clocks generated by the Pico (Target Mode) and outputs the correct data format, you must tie the following pins to Ground:

- Connect **FMT** (sometimes printed as FMY) to `GND`.
- Connect **MD0** to `GND`.
- Connect **MD1** to `GND`.

Once wired, plug the Pico into your computer. It will appear in your system audio settings as a USB input device.

## Part 2: Technical Details (For Developers)

This firmware is built using the official Raspberry Pi C/C++ SDK and the TinyUSB stack. It addresses the lack of native I2S input support in the standard `pico-extras` library by utilizing a custom PIO state machine.

### Architecture

- **USB Protocol**: UAC1 (USB Audio Class 1). Chosen specifically to operate flawlessly within the RP2350's USB 1.1 Full Speed (12 Mbps) hardware limit without driver conflicts on Windows.
- **I2S Role**: The Pico acts as the I2S Controller. It generates all necessary clocks and dictates the bus timing to the peripheral Target ADC.
- **Data Flow**: Audio data is captured by the PIO state machine and transferred to memory via DMA, triggering TinyUSB audio callbacks to stream the data to the host.

### Clock Generation and Synchronization

To ensure perfect USB synchronization and avoid audio drift or buffer overruns, the I2S clocks and the USB polling rate share the exact same hardware origin.

- **System PLL Adjustment**: The RP2350's default 150 MHz system clock is adjusted to 147.456 MHz. This specific frequency allows for exact integer division to derive standard audio sample rates (48 kHz, 96 kHz) without the jitter introduced by fractional dividers.
- **Master Clock (MCLK)**: If the peripheral ADC requires a high-speed system clock (e.g., the PCM1808), it is generated via a hardware PWM slice on `GPIO 12`. For a 48 kHz sample rate, the PWM divides the 147.456 MHz system clock by 12 to output a pristine 12.288 MHz square wave.
- **I2S Clocks**: `BCLK` and `LRCK` are generated directly by the PIO state machine, heavily derived from the same adjusted system clock.

### Building from Source

This project uses standard CMake and relies on the official Raspberry Pi Pico SDK.

**Prerequisites:**
- Raspberry Pi Pico SDK (v2.0.0+)
- Appropriate toolchain package (`arm-none-eabi-gcc` or `riscv-elf-gcc`)

**Standard Build Flow:**
```bash
mkdir build && cd build

# Configure (Default ARM)
cmake -DPICO_PLATFORM=rp2350 ..

# OR Configure (RISC-V)
# cmake -DPICO_PLATFORM=rp2350-riscv ..

# Build
make -j$(nproc)
```

The compiled `pico-i2s-usb.uf2` will be placed in the `build/` directory.

**Advanced Configuration:**
If your SDK or toolchain are in non-standard locations, or your toolchain uses a different naming convention (e.g., on Arch Linux), you may need to specify them manually:

```bash
cmake -DPICO_SDK_PATH=/path/to/sdk \
      -DPICO_TOOLCHAIN_PATH=/path/to/bin \
      -DPICO_GCC_TRIPLE=your-compiler-triple \
      ..
```

*Note: Pre-compiled binaries for standard configurations are available on the [Releases](../../releases) page.*
